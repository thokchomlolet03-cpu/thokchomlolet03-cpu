# University study — rigorous optional depth, not a second course plan

[← Learning Hub](../README.md) · [Active course directory](../WORLD_CLASS_FREE_COURSES.md) · [Mathematics](../mathematics/README.md) · [Credential distinctions](CREDENTIALS.md)

**Curated: 16 November 2026.** This section exists for *when a real question demands deeper academic training*. It is not a list of mandatory courses, a promise of academic credit or a separate time-based curriculum.

## Only a few exceptional entry points

| Real learning question | Original free university resource | Why / readiness |
|---|---|---|
| How do shells, tools, debugging and Git actually work? | **[MIT Missing Semester 2026](https://missing.csail.mit.edu/2026/)** | Directly useful during systems/automation work; take relevant lectures only |
| How do algorithms, memory and software foundations fit together? | **[Harvard CS50x](https://cs50.harvard.edu/x/)** | Optional complete CS foundation; free certificate conditional on assessed submissions; not a Harvard degree |
| Can I build a computer from logic gates upward? | **[Nand2Tetris](https://www.nand2tetris.org/)** | Excellent optional first-principles computer architecture; substantial project work |
| How are mathematical abstractions used in ML or quantum? | **[MIT 18.06SC — Linear Algebra](https://ocw.mit.edu/courses/18-06sc-linear-algebra-fall-2011/)** | Take after basic algebra; real problems, not merely videos |
| Why do operating systems behave this way? | **[MIT 6.1810](https://pdos.csail.mit.edu/6.1810/2026/)** | Advanced C/Unix/kernel lab; study after practical administration and programming |
| What makes a network protocol work? | **[Stanford CS144](https://web.stanford.edu/class/cs144/)** | Advanced C++ and networking; study after Cisco/packet traces |
| How do proofs, counting and graphs justify algorithms? | **[MIT 6.042J](https://ocw.mit.edu/courses/6-042j-mathematics-for-computer-science-spring-2015/)** | Full course lists single-variable calculus prerequisite; select topics after foundations |

**No need to complete all seven.** Most are optional; for immediate infrastructure employment, labs in the [systems workbench](../../systems-infrastructure/README.md) matter more.

The slim [course reference catalog](COURSE_CATALOG.csv) records **selected** university subjects and their access/credential boundaries; the [evidence tracker](EVIDENCE_TRACKER.csv) covers only those surviving entries. They are reference/evidence data, not a second active queue.

## What was removed from this active list, and why

The original 31-course academic shopping list mixed systems foundations with multiple beginner Python alternatives, dated Finnish ECTS campaigns, psychology/design/entrepreneurship electives and advanced specialist subjects. Those are not all necessary for the intended employment path. See [the audit](../CURRICULUM_AUDIT.md) for explicit decisions.

The [Finnish credit audit](FINNISH_CREDIT_OPPORTUNITIES.md) is retained as **historical 2026 research**, not current advice to enroll. The old [six-month sequence](SIX_MONTH_SEQUENCE.md) is a retired plan kept only so historical links do not break. Always verify new academic-year deadlines and international registration requirements directly with the institution.

## Be exact about evidence

A free lecture series is not university enrollment; a free CS50 certificate is not a Harvard degree; a MOOC badge is not recorded ECTS; and a published lab plan is not an independently completed lab. Use [credentials guidance](CREDENTIALS.md) and [evidence template](EVIDENCE_TEMPLATE.md) to record only what actually happened.

For foundational hardware/OS depth, the [computer foundations reference](COMPUTER_FOUNDATIONS.md) remains available as an **optional** conceptual ladder, not a prerequisite for applying to IT roles.
